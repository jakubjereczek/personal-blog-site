# Receiving predictable, machine-readable output

## A way to shorten the AI response

LLMs are designed to function as conversational assistants, which often leads to 'verbosity' - a tendency to produce walls of text filled with conversational filler and peripheral information. While this is helpful for chatbots, it is problematic for system integrations. By enforcing Structured Output, we can constrain the model to return data in a predictable format, such as a JSON response. This approach does more than just ensure data integrity, It significantly reduces token consumption by eliminating unnecessary 'pre- and post-meditations' (conversational intros and outros). Consequently, the model’s attention is focused solely on the required fields, resulting in higher precision and lower latency.

## When is it useful?

The primary use case for Structured Output is the transformation of unstructured, "noisy" text into precise, actionable data records. To move beyond theory, let’s examine a real-world scenario: a real-time monitoring system designed to analyze fan commentary during a high-stakes football match.

In this example, the goal is not to have a conversation with the AI, but to treat the model as a high-speed data processor. By defining a strict contract, we can turn an emotional outburst into a telemetry stream ready for a live broadcast dashboard or a sports analytics database.
To achieve this, provide the model with a clear System Role, a Schema, and Operational Constraints:
```json

System Prompt
Role: Sports Data Extractor (JSON specialist). 
Task: Parse fan commentary into structured telemetry. Constraint: Return ONLY valid JSON. No prose. No markdown tags.

Output Schema:
{
  "timestamp": "ISO8601 string",
  "entities": {
    "teams": ["string"],
    "players": ["string"],
    "officials": ["string"]
  },
  "sentiment": {
    "target": "string",
    "label": "positive | neutral | negative",
    "score": "float (-1 to 1)",
    "emotion": "anger | joy | disappointment | neutral"
  },
  "game_events": {
    "event_type": "goal | penalty | foul | card | none",
    "controversial": "boolean"
  },
  "fan_alignment": "string",
  "predicted_action": "string"
}

Rules:
Strict Rules:
- Use null for missing values.
- Strictly adhere to the pipe-separated enums.

Input Text: ""
```
